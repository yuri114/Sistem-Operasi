KONDISI SAAT INI (setelah Tahap C)
------------------------------------------------------------
- Arsitektur  : x86_64 64-bit Long Mode (IA-32e)
- Resolusi    : 1920×1080 @ 32bpp (VBE linear framebuffer ~8.3MB)
- Memori      : 4-level paging, identity-mapped 4GB, heap 2MB (0x100000–0x2FFFFF)
- Multitasking: round-robin, MAX_TASKS=16, context-switch 64-bit
- Filesystem  : MFS2 — 32 file, 16KB/file
- GUI         : Window Manager (16 window), taskbar, 5 built-in apps
- User space  : Ring-3 isolasi penuh, ELF64 loader, user stack @0x600000
- Kernel size : ~178KB
- Platform    : QEMU qemu-system-x86_64, build via WSL cross-compiler (x86_64-linux-gnu)

TAHAP C — 64-BIT LONG MODE (penulisan ulang arsitektur)
Status: [SELESAI] ✓ Selesai 26 Maret 2026 — build 178 KB, boot ke Long Mode, GUI stabil
Prasyarat: Tahap B/B+ selesai ✓
----------------------------------------------------------------
Tujuan     : Migrasi dari i386 32-bit Protected Mode ke x86_64
             IA-32e Long Mode. Penulisan ulang penuh semua
             komponen low-level kernel.

Sub-tahap:

  [C1] Bootloader & kernel entry 64-bit                           ✓
       - boot.asm: Real Mode → Protected Mode (tidak berubah)
       - kernel_entry.asm [BITS 32]: zero BSS, setup 4-level page
         tables (PML4/PDPT/4xPD) di 0x1000–0x6FFF identity-map 4GB,
         aktifkan PAE + EFER.LME + CR0.PG, load GDT64, far jmp
       - kernel_entry.asm [BITS 64]: reload segs, RSP=0x90000,
         call kernel_main()
       - GDT64: null / kernel CS 0x08 / kernel DS 0x10 /
                user CS 0x1B / user DS 0x23 / TSS64 0x28 (16-byte)
       - Compiler: nasm -f elf64, x86_64-linux-gnu-ld -m elf_x86_64

  [C2] Linker & build system 64-bit                               ✓
       - linker.ld: OUTPUT_FORMAT(elf64-x86-64), . = 0x8000
       - build.ps1: x86_64-linux-gnu-gcc -m64 -mno-red-zone
         -mcmodel=small -fno-pic -no-pie, nasm -f elf64
       - QEMU: ganti qemu-system-i386 → qemu-system-x86_64

  [C3] IDT & ISR 64-bit                                           ✓
       - idt.h / idt.c: gate descriptor 16-byte, offset_hi 32-bit
       - isr.asm [BITS 64]: SAVE_REGS/RESTORE_REGS 15 GPR
         (rax,rcx,rdx,rbx,rbp,rsi,rdi,r8-r15)
       - irq0 timer: context switch current_rsp/next_rsp (uint64_t*)
       - irq1 keyboard, irq12 mouse
       - int80_handler: [rsp+112]=rax→rdi syscall dispatch
       - exc_common: EXC_NOERR/EXC_ERR macros → exception_handler

  [C4] TSS 64-bit                                                  ✓
       - tss.h: struct TSS64 (rsp0/rsp1/rsp2, IST[7], iomap_base)
       - tss.c: isi 16-byte GDT descriptor, ltr 0x28
       - tss64_set_kernel_stack() dipanggil di setiap task_switch

  [C5] Multitasking 64-bit                                         ✓
       - task.h: uint64_t rsp, uint64_t *page_dir
       - task.c: current_rsp/next_rsp (uint64_t*), iretq frame
         ring-0 (3 qword: RFLAGS/CS/RIP) dan
         ring-3 (5 qword: SS/RSP_user/RFLAGS/CS/RIP)
       - task_switch: tss64_set_kernel_stack + vmm_switch_dir

  [C6] VMM 4-level paging                                          ✓
       - vmm.c: PMM bitmap 4096 frame (16MB), frame 0-767 pre-marked
       - vmm_create_page_dir: PML4→PDPT→pd_low, boot PDs shared
         pd_low[0]=0x000000|0x87 (0–2MB), pd_low[1]=0x200000|0x87 (2–4MB)
       - vmm_map_page: walk 4-level, skip 2MB large pages (bit PS)
       - vmm_free_user_memory: free PTs + frame ≥ 3MB + pd_low + pdpt + pml4
       - paging.c: paging_init = no-op (4-level aktif dari kernel_entry)

  [C7] ELF64 loader                                                ✓
       - elf_loader.h/c: Elf64_Ehdr/Elf64_Phdr, e_machine=0x3E
       - Load address: 0x400000 (pisah dari kernel heap)
       - User stack: 0x600000 (1 frame 4KB)

  [C8] Kernel C & syscall 64-bit                                   ✓
       - kernel.c: enter_usermode iretq, exception_handler uint64_t
         tss64_init, print_hex64
       - syscall.c: is_user_ptr(uint64_t), semua return uint64_t,
         kernel_exec / SYS_EXEC memakai uint64_t proc_dir/entry/stack
       - lib.h: syscall0/1/2 return long, (long) pointer cast
       - user.ld: OUTPUT_FORMAT(elf64-x86-64), . = 0x400000
       - memory.c: saved_flags uint64_t (pushf/popf 64-bit)
       - shell.c: uint64_t proc_dir/entry/sp1/sp2
       - paging.c: paging_get_cr0 uint64_t temp register

TAHAP K — GUARD PAGE (STACK OVERFLOW PROTECTION)
Status: [SELESAI] ✓ Selesai 1 April 2026 — build OK
Prasyarat: Tahap C, D selesai ✓
----------------------------------------------------------------
Tujuan: deteksi stack overflow user sebelum ia corrupt heap/code.

RENCANA FONDASI P — THREADING LANJUTAN
Status: [RENCANA]
Prasyarat: Fondasi O selesai ✓
----------------------------------------------------------------
  [F-P1] Thread stack size expansion
         Masalah: stack thread saat ini hanya 4KB (1 halaman 0x1000).
           Fungsi rekursif dalam atau chain panggilan bersarang > ~200
           frame akan overflow secara diam-diam (tidak ada guard page
           per-thread).
         Rencana:
           - Naikkan default stack thread ke 16KB (4 halaman berurutan)
           - Offset slot: 0x700000 + id * 0x5000 (4 halaman data +
             1 halaman guard per slot)
           - Guard page per-thread: halaman pertama di tstack_va
             dibiarkan tidak dipetakan → #PF → "THREAD STACK OVERFLOW"
           - tstack_frame: alokasi 4 frame, simpan frame pertama saja;
             pmm_free_frame × 4 saat exit
           File: src/kernel/task.h, src/kernel/task.c,
                 src/kernel/kernel.c (exception_handler guard zone)

  [F-P2] Multiple waiters per semaphore
         Masalah: Semaphore saat ini hanya menyimpan 1 waiter (int waiter).
           Jika dua thread melakukan sem_wait() bersamaan saat value==0,
           hanya satu yang tersimpan → thread kedua menggantung selamanya
           sampai ada sem_post berikutnya yang kebetulan pick up.
         Rencana:
           - Ganti int waiter → waiters[SEM_WAITER_MAX=4] queue (ring buffer)
           - sem_wait: enqueue current_task, task_block()
           - sem_post: dequeue satu waiter (FIFO), task_unblock()
           File: src/kernel/semaphore.h, src/kernel/semaphore.c

  [F-P3] Thread name customization
         Masalah: semua thread diberi nama "thread" (hardcoded di
           task_create_thread). Shell ps/taskstat tidak bisa
           membedakan thread mana yang mana.
         Rencana:
           - Tambah parameter const char *name ke task_create_thread()
           - syscall SYS_THREAD_CREATE kirim pointer name dari user space
           - lib.h: thread_create_named(fn, arg, name) + thread_create
             meneruskan "thread" secara default
           File: src/kernel/task.c, src/kernel/syscall.c,
                 src/programs/lib.h

  [F-P4] Condition variable (cond_wait / cond_signal)
         Kebutuhan: mutex + cond var adalah pola sinkronisasi standar.
           Saat ini hanya semaphore — tidak bisa atomic "release lock
           dan tidur" yang dibutuhkan pola produser-konsumen yang benar.
         Rencana:
           - condvar.h/.c: struct CondVar { int waiters[CV_MAX=4] }
           - cond_wait(cv, sem): release sem → enqueue self → block
             → reacquire sem saat dibangunkan
           - cond_signal(cv): unblock satu waiter
           - cond_broadcast(cv): unblock semua waiter
           - Syscall: SYS_COND_WAIT(67), SYS_COND_SIGNAL(68), SYS_COND_BROADCAST(69)
           - lib.h: cond_wait, cond_signal, cond_broadcast wrappers
           File: src/kernel/condvar.h, src/kernel/condvar.c,
                 src/kernel/syscall.h/c, src/programs/lib.h

  [F-P5] MAX_TASKS expansion (16 → 32)
         Masalah: MAX_TASKS=16 sangat terbatas.
           shell(1) + proses(1) + 3 thread = 5 slot, tersisa 11.
           GUI app (5) + networking (1) + threads (3) → slot penuh.
         Rencana:
           - Naikkan MAX_TASKS 16 → 32
           - stacks_base: 32 × 8KB = 256KB (heap kernel cukup)
           - Sesuaikan array berdasar MAX_TASKS:
             mailbox[MAX_TASKS][8], fd[MAX_TASKS][8], semaphore waiters
           - task_count scan harus tetap 0..MAX_TASKS-1 (sudah benar)
           File: src/kernel/task.h + semua array yang hardcode 16

  [F-P6] Futex (fast userspace mutex)
         Kebutuhan: sem_wait/sem_post saat ini masuk kernel setiap kali.
           Untuk mutex yang jarang dikontestasi, overhead dua syscall
           per operasi lock/unlock tidak perlu.
         Rencana:
           - SYS_FUTEX_WAIT(70): jika *addr == expected, block task ini
           - SYS_FUTEX_WAKE(71): bangunkan hingga N waiter di addr
           - lib.h: userspace spinlock dengan __atomic_compare_exchange;
             fallback ke futex_wait hanya jika race terdeteksi
           File: src/kernel/syscall.h/c, src/programs/lib.h

  [F-P7] Thread-local storage (TLS)
         Kebutuhan: setiap thread butuh variabel lokal sendiri (errno,
           locale, stack canary) tanpa konflik dengan thread lain.
         Rencana:
           - Alokasikan 1 halaman TLS per thread di VA 0x800000+id*0x1000
           - Set FS base register via SYSCALL saat thread pertama kali jalan
           - lib.h: __thread keyword wrapping ke [FS:offset]
           File: src/kernel/task.c, src/kernel/syscall.h/c,
                 src/programs/lib.h
